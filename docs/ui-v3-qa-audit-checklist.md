## 四、设计师视角：系统性短板分析与深度优化建议（含利弊与隐性代价）

> 遵循客观性原则：**先亮短板，再给建议**；每一项都明确列出**收益**与**隐性代价/风险坑点**，方便您基于完整信息做取舍。

### D1. 建立「弹窗 / 抽屉 / 遮罩」全站 v3.0 统一令牌体系（消除“新旧两张皮”）
- **现状短板**：目前主页面（控制台 / 账户审计 / 节点流量）已达到商业级克制审美，但用户一点击「切换锁定」「分项清理」「支持弹窗」「安全守则」立刻掉回 v2.0 重阴影 + 粗体 + 原生控件时代，破坏整体高端感。
- **建议做法**：
  1. 在 `theme.css` 新增双主题弹窗语义 Token：`--modal-backdrop`（浅色 `rgba(15,23,42,0.28)` / 暗色 `rgba(0,0,0,0.62)`）、`--drawer-backdrop`（浅色 `rgba(15,23,42,0.20)` / 暗色 `rgba(0,0,0,0.46)`）、`--shadow-modal`、`--shadow-toast`；
  2. 统一重构 `PlaybookDrawer`（改为类似「防封宝典」的固定 Header + 扁平文档流 + `ThinScrollArea` + `Esc` 关闭）、`CleanConfirmModal`（去等宽数字、接 `ThinScrollArea`、自绘轻量复选框）、`RiskModal`（补 `ellipsis` 防溢出、统一字体、去硬编码红）、`SupportModal`、`ToastStack`；
  3. 全站所有原生 `<input type="checkbox">`（含实时异常日志流与清理弹窗）统一替换为主题自适应轻量复选框（或 CSS `accent-color` + 暗色边框定制）。
- **隐性代价与风险**：
  - 改动涉及 5 个公共组件，需同步检查并回归与 `RiskModal` / `CleanConfirmModal` / `PlaybookDrawer` 相关的 Vitest 断言；
  - 浅色遮罩调浅后，若背景页面信息密度高，弹窗边缘边界感依赖 `--shadow-modal` 与 `1px solid var(--border-card)` 的精细配比，需真机浅色实拍微调，不能过淡导致发飘。

### D2. 收敛「全站唯一主蓝焦点」，回归侧边栏左下角轻量化进程卡（对齐 A1）
- **现状短板**：目前无论停留在哪个页面，左下角 `Claude 进程` 卡片里那颗全宽蓝色边框按钮「强杀防复活盯防 (45s)」都在持续吸引注意力；尤其在账户审计页（已有右上角「防封宝典」蓝 + 「云端核验」主蓝）时，一屏出现 3 处蓝色抢焦点。
- **建议做法**：
  - 回归 3 份封板原型的 **2 行紧凑结构**：`行1: ● Claude 进程 | 0 残留`，`行2: 已彻底退出 | [🛡️ 盯防 45s]`（闲置态用中性细边框小胶囊，仅在进入「盯防中 / 熔断锁定」激活态时才亮起柔和主蓝或柔丹红）。
- **隐性代价与风险**：
  - 现有测试中对 `btn-start-kill-hold` / `btn-kill-and-hold` / `sidebar-proc-card` 有文案与存在性断言，改造时必须保留原 `data-testid` 且确保 4 种状态（0 残留 / 有进程存活 / 普通盯防倒计时 / 熔断联动锁定）在 188px 窄宽度下不折行、不截断；
  - 按钮变小后，对不熟悉的新手来说“主动提前开启 45s 盯防”的视觉显著度会略降（但日常 95% 场景由系统自动联动或清退触发，反而更符合低打扰原则）。

### D3. 彻底治理账户审计页两处信息拥挤点：顶部档案卡（C2）+ 完整取证日志台（C1）
- **现状短板**：
  - 顶部双层档案卡把 8 个信息/按钮硬塞在 1 行里，导致 `Stripe 直付` 掉行、且右侧两个入口功能重叠；
  - 「完整取证日志台」套在两层外壳里导致 4 张卡片挤爆文字折行。
- **建议做法**：
  1. **顶部档案卡信息分层**：将 `Stripe 直付`（商户渠道）并入第二行元数据（`组织 7aacf131 · 属地 待核 · Stripe 直付 · 注册 33 天 · 本机 28 天`），让第一行保持干净的 `邮箱 + 套餐 + 来源 + 订阅时长`；右侧精简掉冗长的虚线蓝胶囊（将“本地估上限 85”说明并入评分胶囊 hover 气泡或云端核验按钮副提示），右侧只留 **`[85 分 · 本地估]` + `[云端核验]`**，瞬间清爽一倍；
  2. **完整取证日志台去套娃**：嵌入账户审计页时传入 `embedded` 属性，隐藏重复的大标题头、将 4 张独立卡片替换为 v3.0 的 4 等分一体化统计条（`.metric-strip-4`），并将「点击查看明细 ↗」移到第 4 格副行，彻底消除挤压折行。
- **隐性代价与风险**：
  - 精简顶部虚线蓝胶囊（`btn-cloud-prompt-pill`）前必须确认是否有既有单测依赖该 `data-testid`，且未核验用户的“本地估上限 85”强引导曝光会稍微收敛（可通过评分胶囊文字 `85 分 · 本地估（封顶）` 或第 3 项展开提示补偿）；
  - `LogAnalysisPage` 改造需同步确认独立渲染路径与嵌入路径两种模式不互相破坏。

### D4. 控制台右侧详情「结构化实测键值 + 可折叠原始日志」（对齐 A3）
- **现状短板**：当前控制台右侧「真实探针实测数据」直接把多行英文/技术参数 `evidence` 整块丢在等宽代码框里，普通用户一眼扫过去全是技术黑话，找不到重点；而原型 `ui-v3-console-final.html` 的「键值行列表 + 折叠原始日志」可读性高出一个量级。
- **建议做法**：
  - 新增纯前端轻量解析器，优先将 `evidence` 按 `key: value` / `key=value` 解析为优雅的键值行列表（异常值带微圆点高亮），底部附「查看原始探针日志 ▾」折叠区与「复制诊断」按钮；解析失败或纯句段时自动平滑降级为原始文本块。
- **隐性代价与风险（务必注意）**：
  - **高兼容风险点**：后端 16 项真实探针（Rust `preflight`）产出的 `evidence` 文本格式五花八门（有单行中文、多行 `k=v`、括号注释、URL、PowerShell 报错片段），纯靠前端正则解析存在“半截解析反而不如原样清晰”或截断长 URL 的坑；
  - **折中建议**：若不想增加前端解析脆弱性，也可先只做「已通过项补齐单项复测 + 复制诊断轻按钮」+ 去掉 `.guide-box` 二次嵌套框（低风险），等后续后端结构化返回 `evidence_kv` 字段再一步到位做键值行。

### D5. 节点流量页微调：列宽再平衡 + 胶囊格式统一 + QA 数据真实化（对齐 C4 / C6）
- **现状短板**：实时流量表 7 列之间空出 `52px × 6 = 312px` 空白，却把高频域名（Datadog、Anthropic Lab）截断成 `...`；过滤胶囊里 `未收录新域 (1)` 风格突兀。
- **建议做法**：
  1. 将 `.conn-col-head` / `.conn-row-grid` 前两列从 `164px / 140px` 放宽到 `206px / 172px`（总实宽 `818px`，在 `1280px` 视口内容区 `1018px` 下仍有每处 `33px` 的均匀呼吸间隙，且常见域名不再截断）；
  2. 将 `未收录新域 (1)` 统一为 `未收录新域` + 分离浅灰数字 `1`；
  3. 补全 QA 预览数据中后 3 条连接的 `startedAtMs`、节点的 `exitIp` 与 `clashVersion`，让预览态与真实端观感 100% 一致。
- **隐性代价与风险**：
  - 放宽列宽后在 `< 1040px` 极窄窗口下会略早触发横向滚动条（已有 `.table-scroll-x` 兜底，但需在 `1024px` 宽度下复测一遍确认无异常）；
  - 修改 `未收录新域 (1)` 文案前需核查是否有测试正则精确匹配括号格式（如有，保留 `data-testid="btn-filter-unlisted-domains"` 即可）。

### D6. 存量「环境维护」与「守卫配置」页的后续规划（当前红线内未动）
- **现状短板**：两页已通过 `theme.css` 兼容变量在双主题下完整可读无报错，但对比已升级的 3 个核心页面，它们仍使用原生滚动条、旧版 600 字重标题、旧式松散卡片间距与旧式蓝色开关风格，整套软件呈现出“前 3 页 v3.0 + 后 2 页 v2.0”的阶段性断层。
- **建议做法**：本次继续严守边界不大改；待前 3 页与全部弹窗/抽屉打磨到完美后，可单独开一个轻量 **Phase 2（维护页 + 配置页 v3.0 风格统一）** 专门收口。
- **隐性代价与风险**：维护页和配置页交互表单最多（备份还原、网络急救、自启与更新器、阈值滑块），若混入当前轮一起大改会显著拉大回归测试半径，**强烈建议分阶段推进**。
