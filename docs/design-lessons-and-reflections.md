# FD Claude 安全启动器 · 产品设计与工程反思沉淀（长期记忆文档）

> **文档目的**：记录「账户审计（v0.3.0）」历经 12 轮原型打磨与真机排查沉淀下来的**底层思维规律与血泪教训**。不仅记下“要改什么”，更讲清**“为什么当初做错了、为什么这样改才对”**，作为本项目与后续跨版本/跨项目开发的永久准绳，杜绝同类问题反复出现。

---

## 一、信息架构与产品心智反思

### 反思 1：切忌堆砌“能读到但不相关”的数据，用户要的是「防封决策」，不是「文件浏览器」
- **当初犯的错**：早期版本把 `~/.claude.json` 里能读到的各种运维元数据、白名单明文凭据（Secret Sprawl）、第三方 MCP 数量、`org_level_disabled` 全塞进审计页，页面密密麻麻。
- **为什么错了**：
  1. 用户打开「账户审计」的核心诉求是**“提前规避不合适行为降低封号风险”**，而不是看已经发生的历史流水账或跟 Anthropic 风控无关的本地代码安全项；
  2. 把白名单 Token、MCP 安装数与真正会触发封号的跨洲错配、多号混登混在一起，会严重误导用户心智（让人以为装 MCP 或白名单写个密钥也会被封号），制造无意义的焦虑税。
- **永久范式**：每一项进入审计列表的指标都必须回答一个拷问——**“这项异常会直接或高频间接导致账号被审核/限制吗？工具或用户看到后能采取什么具体预防动作？”** 不能回答就果断砍掉（MCP 仅保留极端高频报错风暴静默兜底进日志流，平时 0 噪音）。

### 反思 2：禁止“只看读、不看职责边界”，必须把「用户自省」与「工具可修」及不同修复方式彻底拆分
- **当初犯的错**：早期把「断连回传 Cookie 403」（网络代理层防护）和「本机遥测开关与缓存清理」（本地配置文件写入 + 文件目录清理）揉在一起，把「控制台代理状态 / 防复活盯防 / 日志 403」混成一团。
- **为什么错了**：触发机理不同、处置手段不同的风险项硬绑在一起，会导致按钮语义混乱（点一个按钮根本不知道改了什么），也违反本项目的「系统改写对象分界清晰」原则。
- **永久范式**：
  1. 上方放「需用户自行注意与克制」（事前习惯自省），下方放「工具可介入防御与修复」；
  2. 不同处置动作彻底拆成独立子格，**哪项有隐患只高亮哪项对应的处置按钮**，其余正常格保持静默不动。

### 反思 3：避免“多处重复展示同一信号”与“正常与异常混在同一格染同一种色”
- **当初犯的错**：顶部放了 `归属地 × 当前出口`（下面第 3 项已在监控），又把 `对话可用` 和 `1 条静默监控` 塞在同一格里整体染成琥珀黄。
- **为什么错了**：同一信息重复占版面浪费稀缺首屏空间；把正常的“对话可用”和异常的“1 静默标”合并染黄，会让用户第一眼误以为“对话也不能用了”。
- **永久范式**：顶部只放**账号在云端的 4 项纯净本体状态**（对话可用 / 官方警告与静默标 / Persona KYC / Portal 门户），与下方 7 项零重复；不同维度的状态严格分格分色。

## 二、视觉降噪与交互秩序反思

### 反思 4：保留分层语义 ≠ 满屏刷彩色边框；注意力是稀缺资源
- **当初犯的错**：为了让「官方红线 / 经验预警 / 经验防护」有区分，给 7 行标题前全加了红底红框或黄底黄框的大胶囊；同时顶部第 1 格 `对话可用` 把文字染绿，而第 3/4 格正常项却是绿点 + 白字。
- **为什么错了**：
  1. 当页面里 6/7 的行都挂着红黄彩色边框时，即使它们全部正常，用户的眼球也在被满屏红黄框疯狂抢夺，**真正需要立刻处理的异常项反而被淹没了**；
  2. 正常态有的绿字、有的白字，破坏了视觉系统的一致性信任感。
- **永久范式**：
  - **前置分层标签**：统一中性灰底暗标 + 左侧 `5px` 语义微色点（红点/琥珀点/灰点），保留层级辨识度但把视觉噪音降到最低；
  - **顶部状态卡**：正常态 100% 统一 **`绿点 + 主白字`**，**只有异常项才给文字上色**；
  - **层高与组件家族**：新增页面的列表行高（`padding: 11px 14px`、`14px` 标题、`12px` 副标、`30×30` 灰色图标块）必须严格对齐控制台已有规范，绝不为强行塞满一屏而把行高压扁变挤。

### 反思 5：展开子类的「空间记忆」与「纯只读前置」原则
- **当初犯的错**：把带按钮的可操作格放上面、纯只读无按钮格放下面，导致上高下矮错落不齐。
- **为什么错了**：用户扫视展开面板时，大脑习惯“先看静态参考事实，再看底部可执行的动作”；而可操作子格若因为当前状态正常就藏起来或挪位置，会破坏用户的空间记忆。
- **永久范式**：**永远无需操作的纯只读对照项统一置顶（虚线只读条）**；**支持修复但当前状态正常的子格严格固定在原位不动**，仅在异常时原地亮起主按钮。

### 反思 6：文档型抽屉切忌「卡片套卡片」，主体要服务于阅读心流
- **当初犯的错**：在「防封宝典」抽屉里，评分卡内部每条扣分又套了圆角边框盒，下面知识区每一段又套了独立边框卡，同时把权重表摆在最前面喧宾夺主。
- **为什么错了**：多层嵌套细框线在暗色界面下产生强烈的“表格囚笼感”，打断长文阅读节奏；用户点开「防封宝典」首要诉求是看懂**怎么防封、避开哪些大坑（如虚拟 U 卡/共享代充连坐）**，权重公式只是辅助验证工具。
- **永久范式**：长文宝典采用**扁平文档流 + 极简 `1px` 细分割线 + 左侧 `2px` 语义色条 + `1.7` 舒适行高**，绝不卡片套卡片；正文聚焦高价值防封知识，100 分权重明细放底部默认折叠按需展开。

## 三、产品文案纯净度与黑盒诚实度反思

### 反思 7：绝不把设计评审语、架构术语或工单编号泄露到最终用户 UI 上
- **当初犯的错**：把 `单开手风琴 · 哪项有隐患即高亮对应处置按钮`、`静默标已归入顶部第 2 格`、`T-058补齐`、`与控制台同源`、`顶部为只读对照区` 这些开发/设计沟通语直接写进了页面文案。
- **为什么错了**：这是典型的**「创作者视角错位」**——把给产品经理或自己看的交付说明，当成了给最终用户看的产品文案。普通用户看不懂也不在乎什么是“手风琴”“同源”“T-058”，这类字眼会瞬间拉低软件的商业专业度。
- **永久范式**：交付前必须做一次**全页文案净化扫描**——假设读者是一位第一次装这个软件的普通 Claude 用户，删光所有开发/设计元描述，只保留直白、有行动价值的产品人话（副标题也绝不裸露 `monitoring_notice / flags` 这类英文代码字段，全部译为中文含义）。

### 反思 8：面对黑盒风控与技术盲区，诚实克制就是最高级的专业
- **当初犯的错**：早期曾对社区经验规则写“务必”“严禁”“必封”；也曾把 9 天前滞后的本地缓存额度标成模糊状态、把本地推算的续费日写成精确到期日、留过空的 `+ 多账户` 按钮。
- **为什么错了**：Anthropic 风控是黑盒模型，一旦工具把经验说成铁律、或把旧缓存装成实时、或把未做的功能做成假按钮，用户只要踩过一次不准就会彻底丧失对整个工具的信任。
- **永久范式**：
  1. **3 级客观语气**：官方明文红线用「强烈建议」，社区高频实证用「建议/有助于降低概率」，经验观察窗用「社区经验参考/倾向于」；
  2. **透明边界**：未核验云端或超 7 天衰减时诚实封顶 `85` 分并明示原因；本地推算续费日标 `~`；能查什么（出口 IP、属地、商户）与绝不能查什么（银行卡/U 卡发卡国、Persona 证件国）公开写明；不做空壳假按钮。

## 四、架构安全与底线反思

### 反思 9：单一事实源（控制台与账户审计 100% 同源，绝不精神分裂）
- **当初发现的真机问题**：旧版控制台「单号卫生锁」与「隐私降噪」显示全绿，但真机实测 CLI ≠ Desktop 组织且 `settings.json` 缺 2 项变量。
- **根因**：两处检测读了不同的文件来源，没有收口到同一底层扫描函数。
- **永久范式**：凡在多页面共同呈现的安全项（混登、隐私降噪、归属地跨洲、官方端点防反代），后端强制抽取唯一共享检测与修复函数，确保全软件口径 100% 一致。

### 反思 10：对外查分 API 与额度提精的安全底线
- **核心认知**：
  1. 装了桌面软件的用户直接在界面查看即可，无需画蛇添足做多余的本机桥接；面向未装软件用户的外部 API 极简聚焦为 **`POST /v1/audit/check-sk`（`sessionKey` + `proxyUrl` 代理只读脱敏查询）**，严格做到：只读 GET、明文 `sk` 与代理账密用完即焚零日志落盘、响应全量脱敏、建议传独立代理并诚实标明云端分边界；
  2. 绝不在后台定时轮询官方 `/usage` 或解密 DPAPI Cookie（主动制造异常脚本心跳等于自找风控）；额度统一采用「被动监听本地写盘 + 离线 `.jsonl` 校正 + 手动核验 60s 冷却锁」三层安全策略。
