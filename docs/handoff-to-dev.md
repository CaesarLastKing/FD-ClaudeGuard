## 3. 自初始交接版以来的全部增量变更清单（请开发 AI 逐项核对落实）

> 以下 10 项覆盖自「TUN 与 DNS 拆分」讨论起至当前终版的所有增量需求与优化。

### 增量 1 · TUN 与 DNS 拆分为两项独立实测（必须项共 9 项）
- 控制台「2. 系统防泄漏」拆为 3 项独立必检：
  1. `IPv6 彻底防泄漏（三层实测）` `[管理员一键 + 实测]`
  2. `虚拟网卡接管（TUN 模式）` `[向导 + 实测验收]`：实查 Mihomo `tun.enable == true` 且 Wintun 虚拟网卡在线；
  3. `DNS 防泄漏（Fake-IP 实测）` `[向导 + 实测验收]`：实测 `claude.ai` 解析落入 `198.18.0.0/15` 网段。

### 增量 2 · 各项不通过时的清晰修复闭环
- **本地封号污染残留审查不通过**：自动结束 Claude 进程 → 执行原子 ZIP 备份 → 清理 `%APPDATA%\Claude`、`%LOCALAPPDATA%\Claude`、`~/.claude/telemetry` → 重扫 0 残留变绿。
- **单号卫生锁与第三方 OAuth 审计不通过**：检出非官方 `ANTHROPIC_BASE_URL` 时提供一键清理环境变量；检出混号/跨 `orgId` 时引导走纯净重置或二次确认更新绑定主号。

### 增量 3 · 历史快照原子事务安全规范（防覆盖、防多次还原损坏）
- 每次备份采用**唯一时间戳 + 来源类型命名**（`clean` / `pre-restore` / `manual`），绝不覆盖旧快照；
- 每次还原前**自动先创建「还原前安全点」**，支持随时反悔回滚；
- 还原前强校验 `Claude 0 进程` + `ZIP 完整性` + `2 倍磁盘余量`，采用「解压至临时目录 → 校验通过 → 原子重命名切换」防中途报错损坏原目录；默认滚动保留最近 10 份快照。

### 增量 4 · 支付守则实事求是拆分（与日志分析对齐）
- 拆为两条独立守则（见 `docs/anti-ban-playbook.md`）：
  - `4A. 严禁封后秒切备用号与同机多号轮换` `[可日志联动]`（捕获 `account_banned` / 跨 `orgId` 竞态）；
  - `4B. 支付渠道绝对隔离（银行卡 / 虚拟卡 BIN / Apple ID）` `[人工守则 · 无卡号日志]`（本地日志不记录卡号，诚实标注为人工防线）。

### 增量 13 · 笔记本「休眠唤醒 / 切网 5 秒预阻断安全窗」
- Rust 后端监听 Windows 原生电源事件（`PBT_APMSUSPEND` / `PBT_APMRESUMEAUTOMATIC`）与网卡切换事件；
- 在「守卫配置」新增开关 **`休眠唤醒 / 切网 5 秒预阻断安全窗`（默认开启，绿标推荐）**；唤醒或切 Wi-Fi 瞬间先挂上临时出站阻断，待 Clash 命名管道 + 真实出口探针确认回到白名单节点后再毫秒级自动放行，彻底杜绝“睡醒前 3 秒偷跑”。

### 增量 14 · 全量代理环境变量审计 + 三端（桌面/CLI/网页）同 IP 冲突巡检
- 控制台「3. Claude 卫生 → 单号卫生锁、代理环境变量与三端同 IP 审计」除扫描 `ANTHROPIC_BASE_URL` 外，同步全量扫描系统/终端 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY` 是否指向冲突端口或把 `anthropic.com / claude.ai` 写入直连豁免；
- 同步核验 Windows WinINET `ProxyServer` 与代理端口（`7890`）一致，并提醒关闭 Chrome/Edge 独立分流插件与 WebRTC 公网 IP 暴露，确保桌面端、CLI、网页版三端同 IP。

### 增量 15 · 防火墙「防自锁 / 崩溃与卸载自愈」安全阀

### 增量 17 · Claude 强杀后「防复活持续盯防锁（Kill-Hold）」与全链路配合
- **痛点**：Claude 进程被强杀后常因 Electron 恢复/更新器/CLI/Chrome 桥接在 1~10 秒内自动复活，导致切节点、备份清理或关代理瞬间撞车漏包。
- **核心机制（详看 `docs/architecture-and-design.md` 第 7 节）**：
  - 凡通过守卫手动或自动触发强杀（侧边栏清进程、应急清理、备份重置、快照还原、切节点清进程、紧急熔断），立即进入 **Kill-Hold 押运锁**：后台以 `250ms` 高频盯防全部关联进程树（`Claude.exe`、`claude.exe`、`claude-code`、Claude Chrome 桥接），**默认持续 `45 秒`（`30s / 45s / 60s` 可配，期间只要冒头立刻再杀、累计拦截次数并每次顺延 `+15 秒`）**；
  - 执行 **备份清理 / 快照还原 / 切节点 / 熔断未解除** 期间保持**事务级全程锁定**直到操作彻底完成；
  - 点击「安全启动 Claude」时在拉起前自动优雅释放押运锁，绝不误杀用户正常启动；侧边栏进程卡与悬浮窗 `进程` 微卡片实时展示 `盯防中 (Xs · 已拦 N 次)` 并支持手动一键「解除」。

### 增量 18 · 节点评估新增「Claude + Gemini 双平台可用性与纯净度」及真机表格优化
- **双平台无状态探测（详看 `docs/architecture-and-design.md` 第 5.1 节）**：
  - 节点测速/评估同步做无状态只读探测（不带 Cookie/Token，带并发限流与短时缓存）：① **Claude 支持性**（`Claude ✓` / `CF 403` / `禁区`）；② **Gemini / Google 支持性**（探测 `gemini.google.com` / `generativelanguage.googleapis.com` 是否可用、地区受限或广播 IP 送中，标识 `Gemini ✓` / `受限` / `送中`）；③ **ASN 纯净度**（`ISP` / `机房`）；
  - **严格解耦**：双通节点优先标示推荐，但 **Gemini 不支持绝不阻断 Claude 启动**（仅作选节点参考加分）。
- **真机 UI 顺手优化**：
  - 在「节点流量」表格中将「平台支持 / 纯净度」列排布在延迟与断连列之间（填补当前真机表格的大片列间空白，保持整表列距匀称）；
