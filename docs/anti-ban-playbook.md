# Claude 账号防封实战守则与高危场景清单（FD Claude Guard 联动知识库 v2.0）

> 结合本机 50MB 真实日志取证与 2025–2026 年社区（Reddit r/ClaudeAI、X、GitHub）最新封号复盘整理。  
> **双向联动机制**：其中带 `[可日志/环境联动]` 标记的条目，将由 **FD Claude 安全启动器** 实时监测并在触发时自动点亮对应守则卡片与悬浮窗预警。

---

## 1. 新号注册、付费充值与订阅升降档的「24 小时高敏窗口」 `[可日志联动]`
- **风险原理**：Anthropic 的支付反欺诈与账号复审通常在首次开通 Pro / Max 或**突然跨档升级（如新号直接跳 Max 20x / 短周期降级再升）后的 30 分钟 ~ 24 小时**异步落锤。
- **守则**：前 24 小时温和低并发使用，严禁切节点、严禁换设备；建议在「守卫配置」开启 **24h 冷静保护模式**。
- **工具联动**：监测日志中套餐类型变更（`free → pro → max`）时自动建议开启 24h 冷静保护。

## 2. 严禁将 Pro / Max 订阅 OAuth Token 接入第三方非官方客户端或反代 `[可环境/日志联动]`
- **风险原理**：2025–2026 封号头号重灾区。Anthropic 已部署服务端深度校验，一旦检测到个人消费级订阅 OAuth Token 被喂给非官方套壳客户端、第三方转发网关或伪造 Harness，会直接秒封（程序化调用必须走官方 Console 按量付费 API Key）。
- **工具联动**：扫描本机环境变量（如异常 `ANTHROPIC_BASE_URL` 指向第三方转发）及日志异常 OAuth 刷新，发现立即在守则与控制台标红预警。

## 3. 禁止无人值守全自动循环脚本与异常高并发刷量 `[可日志联动]`
- **风险原理**：消费级订阅（Pro / Max）要求 Human-in-the-loop（人工交互使用）。挂 24/7 定时自动循环脚本、多线程并发爬取、短时间异常 Token 爆发或频繁撞 `429 rate_limit`，极易被自动化滥用模型直接封禁。
- **工具联动**：实时统计 `main.log` 中的活跃 `sideSession` 并发数、连续自动执行时长与 `429` 频次；超阈值时悬浮窗黄灯预警并点亮本条守则。

## 4A. 严禁封后/受限后同机切备用号与多号轮换 `[可日志联动]`
- **风险原理**：① 封号（`account_banned`）后在污染目录直接切备用号，新号 Cookie 会携带被封 `orgId` 发起 `/authorize` 竞态请求，直接触发 Ban Evasion 连坐；② 即使旧号只是触发 **Verification Portal 门户验证（`portal.anthropic.com/verify`，属于风控升级待核验、尚未永封）**，在同一设备/同一 MSIX 数据目录下与主力号反复来回切登，也会通过跨 `orgId` 残留或同设备指纹/遥测关联显著抬高风控权重，将正常主力号一并拖入审核队列。
- **工具联动**：严格区分「永久封禁」与「Verification Portal 验证受限（高危风控升级）」；日志同时审计多 `orgId` / `accountId` 及是否含受限账号混登，一旦命中立刻高亮本条守则并引导走「清零进程 → 原子 ZIP 备份并清理污染目录（含微软商店 MSIX `LocalCache`）」标准止损流程。

## 4B. 支付渠道绝对隔离（银行卡 / 虚拟卡 BIN / Apple ID） `[人工守则 · 无卡号日志]`
- **风险原理**：复用曾关联被封号的银行卡、高危虚拟卡 BIN 或 Apple ID 会触发支付反欺诈直接连坐；若出现 App Store 挂起订阅冲突报错，需先在苹果端取消待结周期。
- **诚实说明**：本地客户端日志不记录银行卡号或虚拟卡 BIN，本条作为明确的人工防线守则提示（绝不伪装成可自动检测日志的条目）。

## 5. 开机自启顺序竞争（Claude 比代理先启动导致裸奔） `[可系统启动项联动]`
- **风险原理**：若 Windows 开机启动了 Claude Desktop，但 Clash Verge 晚几秒才拉起虚拟网卡，Claude 在开机头 5~15 秒会直接用真实本地 IP 联网发包触发 `region_unavailable`。
- **工具联动**：只读检测 Windows 启动项（`Run` 注册表 / 启动文件夹 / MSIX `StartupTask`），**绝不擅自删除用户的启动项**，但若发现「Claude 开启了开机自启」，会在控制台、守则与悬浮窗明确提示风险并指引关闭 Claude 自启或开启本工具开机驻留。

## 6. 节点短期抖动 vs 长期失效、落地 IP 静默漂移 & 三端同 IP `[可节点/流量/环境联动]`
- **风险原理**：① 频繁跨国切节点或“1 分钟内从美国切到日本”极像共享账号；② 很多机场会在**不改节点名**的情况下后台悄悄切换落地 IP，或把用户分到已被 CF 403 拉黑的高危机房共享 IP；③ 若桌面端走美国、Chrome 扩展分流网页版 `claude.ai` 走日本、CLI 残留旧代理变量走别处，同一账号同时多国在线会直接触发风控。
- **守则**：< 2 分钟抖动先等待自愈；主节点确认失效先清零进程优先切**同地区 ISP 热备节点**；被迫跨国切换静默等待 **15~30 分钟**；关闭浏览器独立分流插件与 WebRTC 泄漏，确保桌面端 / CLI / 网页版三端同 IP。

## 7. 敏感内容安全过滤器误触红线（人工避坑）
- **风险原理**：Anthropic 的自动化安全审核对特定领域采取零容忍策略，社区已出现多起正常用户因上传个人医疗体检数据（被误判医疗诊断）、敏感金融信息或含未成年人字眼（哪怕善意如 *“教 10 岁孩子学编程”*）触发误封的案例。
- **守则**：避免在消费级主力账号中上传医疗诊断类原始隐私数据或触发敏感词边界，并养成**定期本地导出重要 Prompt 与项目知识库**的习惯。

## 8. 关代理前看 0 进程雷达、断连热熔断、隐私降噪与时区稳定 `[可进程/系统联动]`
- **风险原理**：Claude 关窗口常缩回托盘，且手动退出最后 1~5 秒会执行 `onQuitCleanup: flushEventQueue` 与 `[plan-usage]` 携带 Cookie 补发请求；若在代理刚断开（`ERR_CONNECTION_RESET` / `socket closed: 1006`）或切为 `direct` 瞬间手动关闭 Claude，极易把带 Cookie 的请求暴露给禁区/直连 IP 撞出 `403 (withheld, 182 chars)`（高度吻合 `region_unavailable` 长度），并在 24~48 小时后异步触发门户验证限制；同时切忌手动改错或频繁跨十余小时来回修改 Windows 系统时区（应优先换近时区节点），按需关闭未使用的 Chrome 桥接减少 `get_device_info` 上报。
- **工具联动**：退出前进程雷达监测、Claude 运行中遇代理离线/关 TUN/切 `direct` 毫秒级 4 层热熔断（跳过 `onQuitCleanup`）、强制将官方隐私降噪配置纳入「必须通过 → Claude 卫生」、NTP 偏差与历史时区跳变监测。
