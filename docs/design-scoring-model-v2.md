## 一、现行评分模型（v1）实机暴露的核心缺陷

1. **未核验云端（信息盲区）虚高染绿且吞掉本地扣分**：
   - 现行 `LocalOnly` 模式从 `100` 起扣再 `min(score, 85)`，导致账号本体完全未核验（注册时间、属地、封号、静默监控标、KYC、Portal 全未知）时直接给出绿色 **`85 分 · 本地估`**（`>=85` 归入 `safe` 绿灯）；
   - 同时如本机存在跨端混登（-10）+ 缺降噪（-3）= `87`，封顶后仍为 `85`，本地隐患被封顶吞噬无法直观体现。
2. **账号本体严重受限权重过轻且无分级硬封顶**：
   - 实机案例（`star***at@outlook.com`）：云端已实锤返回 `activeFlagTypes: ["access_block", "api_disabled:kyc_pending"]` 与 `personaKycStatus: "expired"`，但旧模型把所有警告打包成单一布尔值仅扣 `12` 分，最终得分 **`88 分 · 低危稳健`（绿灯）**，严重误导用户。
3. **Persona KYC 待验证 / 已过期 / 未通过 0 扣分、无封顶**：
   - 旧模型只给 `persona_kyc_verified_over_72h` 加 `+5` 分，对 `pending` / `required` / `expired` / `failed` 完全不扣分也不限制最高分。

## 二、拟定重构方案（v2 · 账号本体 46 分 + 本机与网络防线 54 分）

### 附加机制与色阶
- **致命一票熔断（≤ 15 分 · 红色 `高危警报`）**：`account_banned` / `portal_hold` / `chat_restricted`。
- **未核验云端（`LocalOnly`）基线改为 `70` 起扣**：本机全绿最高 **`70 分 · 待云端核验`**（琥珀色，绝不染绿）；每条本地扣分直接从 70 往下扣。
- **云端超 7 天衰减（`Stale7d`）**：保留既有扣分，上限封顶 **`78`（琥珀色 · 建议重验）**。
- **四档色阶**：`85~100` 绿（低危稳健，必须 7 天内已云端核验且无高危封顶）｜`70~84` 琥珀（建议优化 / 待云端核验）｜`45~69` 橙（中高风险）｜`0~44` 红（高危警报）。
