## 一、[`F-04`] 4 层热熔断机制专项优化 + 运行中警示横幅边界收敛（P1 · ★★★）

### 1.1 现状痛点与源码级根因
1. **痛点 1：控制台「运行中防护警示横幅」把 `Warn` 当 `Fail` 误弹清退警示**
   - 核查 [ConsolePage.tsx](file:///c:/Users/xujun/Documents/ProgramProject/FDtools/src/pages/ConsolePage.tsx#L885-L905)：横幅触发条件为 `snapshot.bgClaudeProcs > 0 && mustFail > 0 && !snapshot.killSwitchActive`。
   - 而 `mustFail` 在 `F-02`（单号卫生锁三态确认）上线后统计的是 `status !== "ok"`（包含了 `status === "warn"` 的单号人工确认项与清记录后提醒换节点项）。
   - **实机后果**：用户只剩 1 个正常单号正在运行 Claude，尚未点「确认继续使用当前号」（状态 `warn`），控制台顶部就弹出警示横幅诱导用户「立即安全退出 Claude」，造成严重误导！
2. **痛点 2：4 层热熔断触发存在瞬时抖动误杀风险，且与切节点事务/主动强杀边界偶发竞争**
   - 节点切换或 Mihomo 重载的 1~2 秒瞬间，代理接口短暂返回瞬时超时/连接重置；若无连续确认窗口（debounce / consecutive-fail）或事务锁互斥保护，可能误判节点离线直接触发防火墙全封锁。
3. **痛点 3：熔断触发后的视觉感知、通知轰炸与恢复闭环不够直觉**
   - 熔断已生效时，控制台缺少一块醒目但克制的**「紧急熔断中」专属状态卡**（一眼说清：何时触发、因为哪一条红线触发、当前哪 4 层已落锁、按哪 3 步安全解除）；
   - 若故障持续存在，系统级 Windows 原生通知 + 应用内 Toast 可能在短时间内重复轰炸；
   - `guard://killswitch` 事件在主窗、侧边栏、HUD 悬浮窗三端的状态字段需严格同步，避免主窗已熔断但 HUD 滞后数秒。

### 1.2 拟定优化方案（5 大确定性改进）

#### 改进 1：严格区分 `Fail`（硬未通过）与 `Warn`（需人工确认/提示）的运行中横幅边界
- 在 `ConsolePage.tsx` 显式拆分两个计数：
  - `mustHardFail = mustItems.filter(x => x.status === "fail").length`（真正破防：代理断连、禁区出口、多号污染、封号实锤、规则缺失等）
  - `mustWarn = mustItems.filter(x => x.status === "warn").length`（人工确认项：单号待确认、清记录后建议换新节点）
- **分级策略**：
  - **仅当 `mustHardFail > 0` 且 `bgClaudeProcs > 0`**：展示红色/高危「运行中防护警示横幅」（提示存在硬性裸奔/违规风险，主按钮为「立即安全退出 Claude 并盯防」）；
  - **当 `mustHardFail === 0 && mustWarn > 0` 且 `bgClaudeProcs > 0`**：**绝不弹清退横幅！** 仅在左侧对应项保持琥珀 `Warn` 标记（或右侧展示温和的一行提醒「有 1 项待人工确认」），不打断正在正常工作的单号。

#### 改进 2：4 层热熔断防误杀边界与触发状态机加固（Rust `killswitch` + `watchdog` + `lib.rs`）
- **触发条件分级（硬红线秒断 vs 瞬时抖动防误杀）**：
  - **立即秒断（0 延迟，绝不姑息）**：
    1. 检测到活跃连接落入 `HK/MO/CN/RU/BY/KP/IR/SY/CU` 禁区或 `DIRECT` 裸连直出；
    2. 系统处于无代理/防火墙缺失且 500ms 雷达抓到 Claude 裸奔启动（`initial_preflight_done == true` 后）。
  - **二次确认去抖（防瞬时误杀，1.5s 复核 2 次）**：
    1. Mihomo 命名管道瞬时断连或节点测速超时（先跳过事务锁 `tx_locked` 窗口，连续 2 次间隔 800ms 确认均不可达再触发熔断，避免 Clash 重载订阅瞬间误杀用户正在写代码的会话）。
- **事务锁绝对互斥**：
  - 用户主动执行「一键修复」「切换节点」「重载脚本」「网络急救」期间持有的 `tx_locked`（或 `kill_hold` 事务态），4 层热熔断的**节点抖动检测**自动挂起（但仍保留禁区直连硬拦截），事务结束后自动恢复。
- **结构化熔断上下文（`KillSwitchState` 扩展只读诊断字段）**：
  - 新增 `triggeredAt`（时间戳）、`reasonCode`（枚举：`forbidden_exit` / `direct_leak` / `proxy_offline` / `bare_launch` / `manual`）、`reasonSummary`（一句话中文人话原因）、`layersApplied`（4 层各自落锁实证：`[进程强杀, 防复活盯防, Clash 掐断, 防火墙封锁]` 的真实布尔/摘要状态）。

#### 改进 3：控制台专属「紧急熔断中」状态卡与 3 步恢复闭环
- 当 `snapshot.killSwitchActive === true` 时，控制台顶部固定呈现专属「紧急熔断保护已激活」卡片（严格遵循 `ui-design-system.md` 语义色令牌，克制不刺眼）：
  - **显示内容**：触发时间 + 人话原因 + 4 层实际生效状态胶囊（如 `进程 0 存活 · 防复活盯防中 · 连接已掐断 · 防火墙已锁出站`）；
  - **引导恢复闭环**：
    1. 第 1 步（看现状）：实时显示当前 12 项必检中仍有几项 `Fail`（若节点离线或 Clash 离线，提供直达「重新检查」/「一键网络急救」按钮）；
    2. 第 2 步（安全解除）：仅在 12 项硬失败归零时高亮主 CTA「解除熔断并恢复通信」；若仍有硬失败，仍保留「强行解除（高风险）」二次确认入口，**绝不把用户锁死**；
    3. 解除后自动同步释放 `kill_hold` 联动锁 + 清理 `FDClaudeGuard_KillSwitch_*` 防火墙规则 + 自动复跑真实探针验证。

#### 改进 4：`guard://killswitch` 全端事件一致性与通知去重节流
- **前后端事件对齐**：无论由 500ms 进程雷达、2s Clash 哨兵、网卡变动回调还是用户手动触发/解除熔断，后端统一通过单一 helper `emit_killswitch_update(app, &state, &snapshot)` 同时向 `main` 与 `hud` 窗口推送 `guard://killswitch` 与 `guard://snapshot`。
- **通知去重防打扰**：
  - 引入基于 `(reasonCode, active)` 的 **60 秒冷却去重器**（位于后端通知发送层）：同一轮未解除的熔断不重复弹 Windows 原生系统通知；
  - 熔断解除时立即重置冷却器，且仅发送 1 条温和的「熔断已解除，守护恢复正常」状态反馈（应用内 Toast 即可，不滥用系统通知打扰）。

### 1.3 方案短板、隐性代价与风险对等分析（必读）

| 维度 | 收益 | 短板 / 隐性代价 / 真实坑点 | 应对措施 |
| :--- | :--- | :--- | :--- |
| **1.5s 二次确认去抖** | 极大降低 Clash 重载/网络闪断导致的误杀 | 在极端“代理真死但 Claude 恰好在 1.5s 内发包”场景下，理论上有最多 `1.5s` 的延迟窗口 | 仅对“管道/延迟超时”启用 1.5s 复核；对“抓到 `DIRECT` 直连或 `HK/CN` 禁区连接”坚持 **0ms 立即秒断**，且依赖 Clash `Script.js` `REJECT` 兜底规则拦住首包 |
| **区分 `Fail/Warn` 横幅** | 彻底消除单号正常运行时误弹清退警示 | 若用户清完封号记录但一直忘了换旧节点（`Warn`），运行中横幅不会强制打断提醒 | 该 `Warn` 仍会在侧边栏控制台数字角标、列表高亮与下次启动前拦截中持续可见，不丢失提醒 |
| **热熔断改写防火墙** | 进程断网最彻底 | 任何代码 Bug 导致退出未清规则都可能残余断网 | 严格复用既有 `rollback` 防火墙自愈钩子 + 退出自动清规则 + 左下角无门槛「网络急救」一键兜底，并补齐正反向闭环回归测试 |

## 二、[`F-03`] 控制台检查项优先级与展示位置调整（P1 · ★★☆ · 需拍板 Q1）

### 2.1 现状痛点
- 当前控制台左侧列表固定展示「必须通过（12 项）」+「建议优化（7 项）」共 19 项，顺序完全写死；
- 当第 10、11、12 项（如单号卫生锁、本地残留、出口一致性）出现未通过时，用户必须向下滚动才能看到失败项，同时上方堆满了 9 条已经绿灯通过的条目；
- 另一方面，全绿（12/12 通过）时，12 条绿灯项仍占据绝大部分高度，把下面 7 条建议项挤到折叠线外。

### 2.2 三套备选方案对等对比（对应 `decisions-open.md` Q1）

| 方案 | 核心思路 | 优点 | 缺点 / 隐性代价 / 真实坑点 | 推荐度 |
| :--- | :--- | :--- | :--- | :---: |
| **方案 A：纯动态置顶 + 已通过沉底** | 组内按 `Fail → Warn → Ok` 自动排序，全部 `Ok` 时可折叠已通过区 | 故障项永远在首屏前 3 行，零滚动排障 | **最大坑点**：用户点「一键修复」后，正在看的条目瞬间从第 1 行跳到第 12 行，产生“刚才那条去哪了”的视线丢失感；老用户肌肉记忆（第几项是什么）会被打乱 | 中 |
| **方案 B：纯固定顺序重排 + 项归属微调** | 保持顺序恒定不跳动，只把最高频/最关键项（如节点出口、单号卫生、本地残留）提到靠前位置 | 位置 100% 稳定，无跳动感，适合形成肌肉记忆 | 一旦靠后的项（如 IPv6、系统时区）出错，依然要滚动才能看见，未解决“故障直达”痛点 | 中 |
| **方案 C：A + B 结合（固定逻辑分层 + 顶部「待处理聚焦」/温和折叠 · 推荐）** | 1. 底层按“**网络出口防线 → 账号与本地卫生 → 系统防漏与守护**”固定逻辑顺序排列（稳定心智）；<br>2. 在列表最顶部提供**仅当有 `Fail/Warn` 时才出现的「待处理摘要区」（或一键筛选胶囊：`全部 / 仅看未通过`）**，默认在有失败项时自动高亮聚焦第 1 个未通过项，但**不破坏下方原列表顺序**；<br>3. 当 12 项必检全绿（12/12 OK）时，支持一键折叠「已通过的 12 项」，默认让建议优化项或摘要更紧凑呈现（记住用户折叠偏好） | 兼顾**异常零滚动直达**与**列表位置永不乱跳**；点击修复后右侧详情保持锁定当前项，绝不会因为状态变 `Ok` 就把当前焦点弹飞 | 比纯方案 A/B 多 1 个极简筛选/折叠交互控件，需严控视觉克制，避免列表顶部堆叠过多标签破坏 UI v3.0 极简风 | **强烈推荐** |

### 2.3 方案 C 拟定细化设计（待你拍板 Q1 后定稿）
1. **逻辑顺序微调（稳定排布，按排障逻辑从外到内）**：
   - 必须通过（12 项）：`Clash 内核在线` → `策略组与全家桶规则锁死` → `当前出口 IP 地区与纯净度` → `单号卫生锁` → `本地封号污染残留审查` → `官方 API 端点防反代` → `防漏链与 DNS/TUN/IPv6/WebRTC/定位` → `防火墙守护权限`（把用户最常关注、最易变动的 5 项前置到首屏前 5 行！）。
   - 建议优化（7 项）：按实用高频度前置 `开机自启顺序检查`、`系统时区与出口一致`、`隐私降噪开关`，其余低频项置后。
2. **「异常直达」不跳动机制**：
   - 在左列「必须通过」分组头右侧仅放一个极简切换胶囊：当存在 `Fail/Warn` 时显示 `仅看未通过 (N)`（点击可一键只看问题项；默认展示全部但**自动滚动聚焦并选中第 1 条 `Fail` 项**）；
   - 当用户正在查看某条 `Fail` 项并点击「一键修复」使其变成 `Ok` 时，**右侧详情保持停留在当前项展示绿色成功结果**，绝不强行跳走！
3. **全绿态轻量化折叠**：
   - 当「必须通过」12/12 全绿时，允许点击分组头一键折叠/展开（默认保持展开或记住上次折叠态，避免新用户误以为检查项不见了）。

## 三、本批影响面与验收标准
- **涉及文件**：
  - `F-04`：`src-tauri/src/killswitch/mod.rs`、`src-tauri/src/watchdog/mod.rs`、`src-tauri/src/lib.rs`、`src/pages/ConsolePage.tsx`、`src/components/Sidebar.tsx`、`src/components/HudCard.tsx`、`src/stores/guardStore.ts`、`src/types/guard.ts`
  - `F-03`：`src/pages/ConsolePage.tsx`、`src-tauri/src/preflight/mod.rs`（仅调整展示顺序元数据，不改探针 ID 与检测契约）
- **保护边界（严禁误伤）**：
  - 所有 19 项探针 `id` 保持 100% 不变（防破坏 `ipc`、单测、埋点与侧边栏角标联动）；
  - 任何熔断解除操作必须保证 `FDClaudeGuard_KillSwitch_*` 防火墙规则 100% 清除且不自锁。
- **验收判据**：
  1. 单号运行中仅存在 `Warn`（待确认）时，控制台**不弹出**高危清退横幅；注入真 `Fail`（如断代理）时立刻弹出；
  2. 模拟 Clash 短暂重载（< 1s）不误触发熔断；模拟真实禁区/直连时 0 延迟秒断，主窗专属熔断卡 + 侧边栏 + HUD 三端同步，60s 内通知不重复轰炸，一键解除后 100% 恢复通信；
  3. 控制台双主题下「异常聚焦 + 筛选 + 修复不跳焦点」体验丝滑，无文字截断或错位。
