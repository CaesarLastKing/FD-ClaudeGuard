## 一、[`F-06`] 按分类完善账户审计体检项（P1 · ★★☆ · 需拍板 Q2）

### 1.1 现状痛点
- 账户审计右侧「一、需用户自行注意与克制」目前仅有 2 项（拆分 `F-05` 后为 3 项：高敏观察窗、支付风控、自动化机刷节律）；
- 许多导致封号的高频人为因素（例如**买号/合租号来源、黑卡/虚拟卡 BIN 连坐、跨设备/多浏览器指纹混用、代理 IP 质量与合租机场污染、敏感提示词/内容安全红线**）目前只能散落在长篇文字里，用户缺少结构化的自查锚点。

### 1.2 核心架构提案：建立 5 大统一分类维度（同步作为 `F-09` 防封宝典分类真源）

将「一、需用户自行注意与克制」与「二、工具可介入防御与修复」用清晰的分类体系贯通：

| 归属区 | 分类维度 | 体检项构成 | 数据来源 |
| :---: | :--- | :--- | :--- |
| **一、需用户自行注意与克制** | **1. 账号来源与高敏观察窗** | 新号 (<7天) / 过 KYC (<72h) / 套餐跳变 + **账号来源避坑提醒（自注册 vs 买号/合租/成品号）** | 云端/本地实测 + 自查指引 |
| | **2. 支付方式与账单隔离** | 订阅支付方式 / 24h 支付复审窗 + **支付源四同自查（发卡国/账单区/出口 IP/一卡一号，严禁共享虚拟卡 BIN）** | 云端/本地实测 + 自查指引 |
| | **3. 使用方式与人机节律** | 自动化机刷 / 429 限流 / 定时任务 + **高危用法自查（高频并发/无头脚本/敏感内容误触）** | 本地日志实测 + 自查指引 |
| | **4. 设备指纹与网络来源自判** | **新增轻量自查卡**：本机/移动端/网页端设备一致性、浏览器无痕/隔离环境、住宅原生 IP vs 万人共享机场段区分 | 半自动实测（结合当前出口 ASN/ISP 类型）+ 自查指引 |
| **二、工具可介入防御与修复** | **5. 本机与网络 5 道硬防线** | 沿用 `F-07` 重排后的 5 项（1. 归属地与出口 → 2. Clash 断连防护 → 3. 多号混登残留 → 4. API 防反代 → 5. CLI 遥测降噪） | 100% 真实探针 + 一键修复 |

### 1.3 Q2 关键形态二选一（优缺点强制对等分析）

| 形态 | 核心交互 | 优点 | 缺点 / 隐性代价 / 真实坑点 | 推荐度 |
| :--- | :--- | :--- | :--- | :---: |
| **形态 ①：交互式自评勾选（写入本地档案并参与扣分/提示）** | 用户手动勾选“我用的是虚拟卡 / 买来的号 / 共享机场”，工具据此动态改提示甚至扣分 | 个性化强，能帮新手量化自身人工隐患 | 1. **污染实证可信度**：机器真实探针分数和用户随手乱勾的主观分混在一起，会导致“分数失真”且历史归档难以复盘；<br>2. **维护负担大**：每加一个自评选项都要设计持久化 Schema、跨号重置、防误勾清空；<br>3. 多数用户懒得手动填表，勾选框长期停在默认态 | 低 |
| **形态 ②：半自动实测 + 可展开分类避坑自查清单（不介入机器评分 · 推荐）** | 工具能测的数据照常实测（如当前节点是否共享机房段、支付方式、429、新号天数），工具测不到的部分以**结构化 3~4 条自查红线要点**呈现，并带「查看防封宝典对应章节」直达链接 | 1. **严守实证与经验边界**（机器实测就是实测，人工自查就是自查，零假数据）；<br>2. **零配置负担**，打开即懂，视觉高度克制；<br>3. 与 `F-09` 防封宝典天然 1:1 联动 | 无法记录“用户私下换过几次黑卡”这类纯线下行为到分数里（但本就无法机器验真，诚实边界反而是产品专业度的体现） | **强烈推荐** |

## 二、[`F-09`] 「防封宝典」按分类体系重构注意事项（P2 · ★★☆）

### 2.1 现状痛点
- 当前 [AccountAuditPage.tsx](file:///c:/Users/xujun/Documents/ProgramProject/FDtools/src/pages/AccountAuditPage.tsx#L2681-L2950) 中的右侧抽屉「防封宝典」与 [playbooks.ts](file:///c:/Users/xujun/Documents/ProgramProject/FDtools/src/data/playbooks.ts) 内容存在**双源分散**问题，抽屉内按旧版“4 大雷区 + 零散清单”堆砌，和左侧体检项没有一一对应关系，用户看到某项 `Warn` 后还要在抽屉里从头往下翻。

### 2.2 拟定重构方案
1. **单一真源沉淀**：将防封宝典全部章节结构化抽离到 `src/data/playbooks.ts`（按与 `F-06` **完全一致的 5 大分类**组织：账号与观察窗 / 支付与账单 / 网络与出口 IP / 设备与多号隔离 / 使用节律与合规红线），消除 `AccountAuditPage.tsx` 中的大段硬编码 JSX 文案；
2. **明确标注依据层级**：每条宝典规则强制带 1 个小标签区分 **`官方明文红线`**（如禁区 IP、反代 OAuth、Cookie 断连回传）与 **`社区高发经验`**（如过 KYC 72h 观察、24h 冷静期、虚拟卡 BIN 连坐），绝不把社区经验夸大成官方铁律；
3. **体检项 → 宝典 1:1 锚点直达**：
   - 在每张体检卡片底部的建议栏增加轻量文字链「查看宝典详解 →」，点击后直接滑出防封宝典抽屉并**自动定位/高亮滚动到对应分类章节**；
   - 抽屉顶部增加 5 个紧凑分类切换锚点（Pill Tabs），方便按主题秒速检索。
4. **短板/注意**：重构 `playbooks.ts` 结构时，需核查现有 UI 单测（如 `v030_account_audit.test.tsx`）中对宝典标题文案的断言并同步更新，确保测试语义不丢失。

## 三、[`F-08`] 100 分制评分权重体系重构 v2（P2 · ★★☆ · 需确认是否同批启用）

### 3.1 既有草案摘要（真源：[design-scoring-model-v2.md](../../design-scoring-model-v2.md)）
- **解决的 3 个真实现网误导问题**：
  1. `LocalOnly`（未核验 `sk`）不再虚高染绿 `85 分`，改为 **`70 分` 起扣（琥珀色 `待云端核验`）**，且本地扣分不再被 85 封顶吞掉；
  2. 严重限制标（`access_block` / `api_disabled` / `subscription_pause` / `billable_usage_paused`）从仅扣 12 分改为 **`-22 分 + 硬封顶 ≤ 58`（橙色 · 中高风险）**；
  3. Persona KYC 待验证 / 已过期 / 未通过从 0 扣分改为 **`-14 分 + 硬封顶 ≤ 65`（橙色 · 中高风险）**。
- **新权重分配**：账号本体与云端实证 **46 分** + 本机与网络防线 **54 分**；超 7 天云端快照封顶 **78 分**；致命封号/Portal Hold 一票熔断 **≤ 15 分**。

### 3.2 必须提前亮明的短板与取舍（为何建议单独拍板）
- **短板 1（新用户心理观感偏严厉）**：未贴 `sk` 的全新用户即使本机 12/12 全绿，账户审计页也只能看到 **琥珀色 `70 分 · 待云端核验`**，部分只想用本机守护、不想提供 `sk` 的开源用户可能会误以为“被逼着交 `sk` 才能拿绿灯”。
  - **缓解设计**：若启用 v2，必须在分数旁并列给出极简副标 **`本机防线 54/54 满分 · 账号本体待核`**，明确告诉用户“不是你有故障，而是账号云端状态未查”，消除焦虑。
- **短板 2（前后端 + 宝典权重表三处联动）**：需同步修改 `src-tauri/src/account_audit/score.rs`、历史快照重算兼容性（老缓存里旧分数是否展示“旧模型分”或按新公式重算）、以及防封宝典里的权重说明表。
- **建议**：若你担心新用户观感，可先在第三批落地 `F-06 + F-09`，把 `F-08` 放至本批末尾确认文案后再开；若你认可「宁严勿松、绝不给严重受限号打 88 绿灯」，则直接同批落地。

## 四、[`F-11`] 无/有 `sk` 刷新体验边界收口（P2 · ★☆☆ · 需拍板 Q4）

### 4.1 现状复核（对照 `v0.4.1` 已落地能力）
- `v0.4.1`（`BUG-41-06`）已彻底修复了「查过 `sk` 切号丢快照」与「实时出口误拼旧 `TPE` 边缘码」两大核心痛点；

  1. **无 `sk` 切换新号后的刷新反馈**：本机桌面端退出旧号并登录新号（未贴新号 `sk`）后，点「刷新本机审计」时，顶部若能用 1 行 Toast 明确提示「已检测到桌面端切换为新账号 `xxx`，旧账号云端快照已安全移入左侧历史归档」，用户会更安心；
