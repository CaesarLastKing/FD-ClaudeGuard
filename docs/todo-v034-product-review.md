## 一、已实证定位的 4 个直击痛点（含精确代码根因）

### 1. 账户审计“新登录账号被老档案锁死”且不标多份登录态（P0）
- **精确代码根因**：
  1. `src-tauri/src/account_audit/mod.rs:879-904`：只要做过 1 次 `sk` 核验，`account-audit-cache.json` 的唯一槽位 `profiles["default"]` 使 `cloud_verified` 恒为 `true`，后续扫描无条件展示旧 `cloud_snap`（`email`/`orgId`/`plan`/4 格云端态），完全忽略本地新登录的账号。
  2. `src-tauri/src/account_audit/local_scan.rs:1455, 1545-1552`：`org_set` 使用 `BTreeSet` 按字典序而非最近活跃时间排序，`org_id_prefixes.first()` 在新号字母序靠后时永远选中老号。
  3. `src/pages/AccountAuditPage.tsx:1584`：左栏标题硬编码 `当前档案 (1)`，未渲染已检测到的多份账号状态。
  4. 执行「清理登录态」后未同步使 `profiles["default"]` 的旧云端快照失效。
- **改造方案**：
  - `DesktopLogsSummary` 新增 `latest_active_org_prefix: Option<String>`（综合 `config.json` 的 `lastActiveOrg` 与日志尾部最新行时间戳提取当前真正在登的号）；
  - 当本地最新活跃号与旧云端缓存 `orgId` 不一致时，**不再用旧缓存冒充当前主号**，改为：主视图切换到最新活跃号（标注「新登录 · 待 sk 核验」），同时在拓扑与左栏明确列出全部检测到的登录/残留态（如 `当前档案 (2)` + 红标提示「存在旧号缓存/多号混登风险，建议清理后单号使用」）；
  - `account-audit-cache.json` 改为按 `orgId` 分桶保存云端快照（支持切回老号时复用有效缓存、绝不串号），并在清理某端登录态时同步标记对应缓存失效。
- **短板与边界**：桌面端本地日志不含明文邮箱，新号在用户主动核验 `sk` 前只能展示 `新登录桌面账号 (org xxxxxxxx · 待 sk 核验)`；若仅在网页端切换而未启动桌面端，本地无法无感感知网页 Cookie 变化。

### 2. 注册天数 / 订阅天数 / KYC 小时数静态冻结 + `Free` 误显“订阅 40 天”（P0）
- **精确代码根因**：
  1. `src-tauri/src/account_audit/cloud_probe.rs:774-799, 929-939`：核验瞬间算死静态整数 `accountAgeDays` / `subscriptionAgeDays` / `personaKycAgeHours` 落盘；`account_audit/mod.rs:1009-1025, 1285-1299` 后续只读静态值不随 `now_ms` 推进，导致 KYC 过 72h 后仍长期卡在 61h 高敏观察期扣分。
  2. `src-tauri/src/account_audit/cloud_probe.rs:795-799`：无论账号是否为 `Free`，直接用 `primary_org.created_at` 充当 `subscription_age_days`，导致截图出现「`Free 无订阅` 却显示 `订阅 40 天`」的自相矛盾。
- **改造方案**：
  - `CloudProbeSnapshot` 持久化原始 ISO 时间戳（`account_created_at`、`subscription_created_at`、`persona_kyc_completed_at`），每次构建报告用 `now_ms` 实时重算注册天数、订阅天数与 KYC 已过小时数（兼容旧缓存：缺 ISO 时按 `(now_ms - verified_at_ms)` 增量递推）；
  - 当 `plan == "Free"` 时，`subscription_age_days` 强制为 `None`，界面不显示“订阅 X 天”胶囊与“已订阅 X 天”子项。
- **短板与边界**：本地时间递推只负责自然时间流逝，无法感知云端中途退订、升级套餐或重新触发 KYC，超过 7 天仍需按需重验 `sk` 校准云端状态。

### 3. 更新模块“双按钮职责混乱 + 双转圈”（P1）
- **精确代码根因**：`src/pages/SettingsPage.tsx:188-202`（页头右上角「检查更新」按钮）与 `283-315`（卡片右侧「已是最新版本 / 正在检查版本...」按钮）重复绑定同一 `updateChecking` 状态与 `handleCheckUpdate`，导致：① 检查时上下两个按钮同时转圈；② 把只读状态「已是最新版本」做成可点按钮。
- **改造方案（克制收口，不做整页改版）**：
  - 移除页头右上角重复的「检查更新」按钮；
  - 「客户端版本与自动更新」卡片标题行展示**纯只读状态标签**（`v0.3.3` + `已是最新版本` / `发现新版本 vX.Y.Z` / `检查失败`）；
  - 卡片右侧只保留 **1 个明确的操作按钮**（「检查更新」→ 检查中仅此处转圈 → 有新版时切换为「立即更新 vX.Y.Z」）+「GitHub 官网」。
- **短板与边界**：用户滚动到配置页最底部时若要检查更新需滚回顶部卡片；但单入口彻底消除双转圈和“文案像按钮”的误解。
