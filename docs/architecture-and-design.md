# FD Claude 安全启动器（FD Claude Guard）产品与架构设计文档（v1.6 防封深度加固定稿）

> **产品名称**：FD Claude 安全启动器（英文代号：**FD Claude Guard**；主窗口左上角副标题显示为 **`Fuck Dario！！！`**）  
> **版本**：v1.6（新增：落地 IP 静默漂移 + ASN 纯净度、Anthropic 真实可达探针、休眠唤醒 5 秒预阻断安全窗、全量 CLI/WinINET 代理与三端同 IP 审计、防火墙卸载/崩溃自愈安全阀）  
> **技术栈**：Tauri v2（Rust + React 19 + TypeScript + Tailwind CSS v4 + **HeroUI (`@heroui/react`)** + Lucide 线性图标）  
> **目标平台**：Windows 11（原生右上角窗口控制，适配 MSIX 版 Claude Desktop & Claude Code CLI + Clash Verge Rev）  
> **UI 与视觉验收规范**：完整 Design Tokens、组件标准与 16 项 1:1 视觉 QA 门禁详见 [`docs/ui-design-system.md`](./ui-design-system.md)

  - **整卡任意位置拖拽（Drag Anywhere）**：按住悬浮窗任意非顶栏按钮区域拖动超过 `5px` 死区即进入平滑拖拽（轻点 `< 5px` 正常跳转控制台，拖拽松手拦截 `click` 防误触）；在贴边滑出态按住任意位置拖走时自动无缝解除贴边；
  - **单坐标零偏移贴边隐藏（Edge Dock）**：收起态仅屏幕右边缘 `20×84px` 极简耳标响应鼠标（含状态灯 + 细拉手 + 微尖角，绝不远距离误触）；贴边滑出态、常规固定态与隐藏/显示均严格共享同一纵坐标与停靠边距，切换时禁用单帧过渡确保 **像素级 `0px` 偏移、零闪烁**。
- **流量与日志消警闭环（防告警疲劳，不删原始日志）**：
  - **流量异常**：采用 **滚动 12 小时拦截窗口**（超 12h 或重启后自动沉降历史归零），12h 内提供「全部标为已处理」提前清零角标并保留历史明细；正处于熔断阻断态时禁止手动清零；
  - **日志异常**：仅对 **近 24 小时 / 上次已读游标之后的增量异常** 亮红灯（封号污染残留仍作为启动前必须项硬门禁）；展开异常条除定位原文与安全守则联动外，污染/连坐类提供「前往环境维护：备份并重置目录」，断连/429 瞬时预警类提供「标为已读（推进游标）」——**绝不篡改或删除 Claude 原始日志文件**。
- **单一主焦点按钮原则（Single Primary CTA）**：主控制台同屏仅保留一个蓝色 Primary 主按钮（`≥2` 项未通过时右上角显示蓝色「一键处理全部 (N)」，右侧单项按钮降级为中性高对比次级按钮；仅剩 `1` 项时唯一蓝焦点留给右侧单项处理；全绿时右上角亮起蓝色「安全启动 Claude」）；悬浮窗作为独立桌面窗口，其底部待办/启动 CTA 统一采用主操作蓝 `#006FEE` 保持肌肉记忆一致；「导出脱敏问题包给 AI 分析」采用轻量文字链，默认保存至 `%USERPROFILE%\Desktop\FDClaudeGuard-诊断包-YYYYMMDD-HHMM.zip` 并同步复制脱敏上下文到剪贴板，Toast 内提供「打开所在文件夹」。
- **事件驱动 + 15 分钟巡检双引擎 & 三档梯度提醒**：
  - **毫秒级事件驱动（即时触发）**：代理断连、节点漂移禁区、Claude 裸奔拉起、漏规则掐断、日志新写入高危报错、Windows 网卡切换/休眠唤醒；
  - **15 分钟定时巡检（外网兜底）**：外网出口 IP/地区、IPv6 外网探针、Fake-IP DNS 实测、Anthropic 官方状态页 API、NTP 时钟偏差；控制台副文展示 `事件实时监听中 · 全量巡检 MM:SS`；
  - **三档梯度提醒**：① **危急级**（必须项变红/熔断/防裸奔）：悬浮窗红框脉冲闪动、贴边态自动临时滑出 4.5s、**悬浮窗隐藏态强制弹出 Windows 11 原生高优先级通知（含直达定位按钮与可选提示音）+ 任务栏托盘红框闪烁（不可静音）**；② **预警级**（单次漏规则/429 限流）：悬浮窗微卡片脉冲 2 次 + 可被顶栏铃铛静音的普通通知；③ **静默级**（例行巡检全绿）：静默刷新零打扰（同类事件 60s 合并去重）。

## 2. 视觉与排版规范（HeroUI）
- **色彩**：安全绿 `#17C964`、警告黄 `#F5A524`、**标准警示红 `#EF4444`（深色高亮 `#F87171`）**、主操作蓝 `#006FEE`。
- **单色收色层级 & 4pt 字阶**：正常项一律中性单色，仅异常与待优化项点亮红/黄语义色；主标题 `20px/600`、分组 `14px/600`、列表项 `14px/500`、副文 `12px/400`、统计数 `24px/600 tabular-nums`；全宽配置页副文允许完整展示/合理折行，严禁无故在窄宽度处提前截断。
- **文案洁净规范**：界面仅保留面向终端用户的专业产品文案，**严禁在 UI 中出现“已并入”“已按要求”“同步自某文档”等开发过程批注**。
- **窗口与浮窗顶栏图标规范**：主窗口标准 Windows 11 右上角控制键（`─` / `□` / `✕`）；悬浮窗顶栏全部采用标准 Lucide 描边图标（`arrow-right-to-line / arrow-left-from-line` 贴边、`pin` 置顶、`chevron-up` 旋转折叠 | `1px` 分割线 | `home` 控制台、`x` 隐藏到托盘）；**开关型按钮选中态严禁使用彩色底块或底部短横线，统一仅通过纯图标实心/高对比亮色表达状态**。

## 3. 启动前环境体检（两级 · 三大纯粹操作边界 + 每项独立修复闭环）

> **分类铁律**：严格按 **「改谁就归谁（操作对象零交叉）」** 划清 3 条边界，凡不适合绑在一起修的坚决拆开；每项不通过时故障定位唯一、修复按钮唯一、绝不误伤其他层。

### 一、必须通过（10 项硬门禁 · 任一未过即锁定「安全启动 Claude」）

#### 1. 代理与节点（仅操作 Clash Verge / 节点，绝不动 Windows 与 Claude）—— 5 项
1. **代理引擎在线与端口独占** `[自动一键]`
   - 查：Clash 命名管道存活、`7890` 监听、无 `12334 / 10808 / 7897` 冲突代理。
   - 修：拉起 Clash Verge 或提示关闭冲突代理进程 → 实测独占变绿。
2. **策略组与全家桶规则锁死** `[向导 + 实测验收]`
   - 查：`Claude-Fixed`（`select` 手动模式）存在、全家桶域名与进程规则命中、Mihomo `ipv6: false`。
   - 修：仅备份并写入覆写规则 `profiles\Script.js` → 指引 Clash 重载 → API 实查生效变绿。
3. **虚拟网卡接管（Clash TUN）** `[向导 + 实测验收]`
   - 查：Mihomo `tun.enable == true` 且 Wintun 虚拟网卡在线。
   - 修：仅指引在 Clash Verge 首页打开 TUN 开关（或安装 Service Mode）→ 实测 API 与网卡在线变绿。
4. **DNS 防泄漏（Clash Fake-IP）** `[向导 + 实测验收]`
   - 查：Mihomo `dns.enhanced-mode == fake-ip` 且实测解析 `claude.ai` 落入 `198.18.0.0/15`。
   - 修：仅将 Fake-IP DNS 段写入覆写配置 → 重载后真实解析 `claude.ai` 验收变绿。
5. **出口节点合规与真实可达性** `[自动一键 / 选节点]`
   - 查：出口国家白名单 + 历史落地 IP 静默漂移比对 + 免费 IP 情报识别 ASN 纯净度（ISP 住宅 vs 机房/Proxy）+ 无状态 TLS/HTTP 探测 `api.anthropic.com / claude.ai`（筛掉 CF 403 拉黑废节点）。
   - 修：漂移禁区或超时 → 一键切回安全同区热备；CF 403 拉黑或脏落地 → 跳转「节点流量」按纯净度重选 → 复测通过变绿。

#### 2. Windows 系统环境（仅操作 Windows 网卡 / 环境变量 / 系统代理，绝不动 Clash 与 Claude）—— 2 项
6. **Windows 网卡 IPv6 禁用** `[管理员一键 + 实测]`
   - 查：活跃物理网卡与 Mihomo 网卡 `ms_tcpip6` 绑定 + 注册表 `DisabledComponents` + 真实外网 IPv6 不可达探针。
   - 修：仅禁用活跃网卡 `ms_tcpip6` 绑定 → 真实发起外网 IPv6 探测确认无法出网才变绿。
7. **系统代理与环境变量冲突排查** `[自动一键]`
   - 查：扫描用户/系统环境变量中冲突的 `HTTP_PROXY / HTTPS_PROXY / ALL_PROXY / NO_PROXY`（端口冲突或直连豁免 `anthropic.com / claude.ai`）、第三方 `ANTHROPIC_BASE_URL`、以及 Windows WinINET `ProxyServer` 端口一致性。
   - 修：精准列出冲突项 → 一键备份并清理冲突环境变量 / 校准 WinINET 端口（**绝不碰 Claude 账号目录**）；提醒浏览器关闭独立分流插件与 WebRTC 暴露，确保桌面/CLI/网页三端同 IP。

#### 3. Claude 本机卫生（仅操作 Claude 目录与 `settings.json`，绝不动系统与代理）—— 3 项
8. **本地封号污染残留审查** `[自动一键]`
   - 查：扫描 Claude 本地日志与目录是否存在 `account_banned` 等封号污染记录。
   - 修：自动结束进程 → 创建原子 ZIP 备份 → 清理 `%APPDATA%\Claude`、`%LOCALAPPDATA%\Claude`、`~/.claude/telemetry` → 重扫 0 残留变绿。
9. **单号卫生锁（防混号与跨 `orgId`）** `[引导二选一确认]`
   - 查：核对本机登录态/日志 `orgId` 与唯一绑定主号一致，无多号轮换或跨 `orgId` 404 竞态。
   - 修：**绝不擅自乱删**：① 误串旧号 → 引导走「备份并纯净重置目录」；② 明确永久更换主力新号且环境干净 → 二次确认后更新绑定主号。
10. **官方隐私降噪开关 & 遥测缓存** `[自动一键]`
    - 查：核验 `~/.claude/settings.json` 已写入官方降噪环境变量且 `~/.claude/telemetry/` 为 `0 B`。
    - 修：仅合并写入 `settings.json` 降噪字段并清空 telemetry 缓存（**绝不碰账号登录态与聊天记录**）。

### 3.1 历史快照原子事务安全规范（防覆盖、防多次还原出错）
- 每次备份使用唯一时间戳 + 来源类型命名（`clean` / `pre-restore` / `manual`），绝不覆盖旧备份；
- 每次还原前自动先生成「还原前安全点」，支持随时反悔回滚；
- 强制校验 Claude 0 进程、ZIP 完整性与 2 倍磁盘余量，采用「解压至临时目录 → 校验通过 → 原子重命名切换」防中途报错损坏原目录；默认滚动保留最近 10 份快照。

### 3.2 Claude 官方状态与诊断数据采集（融入日志分析与 AI 脱敏诊断包）
- 实时拉取 **Anthropic 官方状态页 API**（`https://status.anthropic.com/api/v2/summary.json`），第一时间区分“官方宕机/529”与“本地账号/IP 风控”；
- 零侵入采集脱敏后的官方诊断元数据（`system-info.txt`、`vm-info.json`、`mcp-info.json`、`supported-features-info.json` 与 `~/.claude/settings.json`），一并打入 AI 脱敏排障包。

### 二、建议优化（3 项 · Windows 系统辅助项，不阻断启动，每项均具备独立处理与复测闭环）
1. **开机启动项顺序风险检查（Clash / Claude）** `[只读风险监测]`
   - 查：只读检测 Windows 启动项中 Clash Verge、Claude Desktop 与本工具自启状态；**绝不擅自删除用户的启动项**。
   - 处理：发现 Claude 开启自启（存在早于代理启动裸奔风险）时标黄警示，提供打开 Windows「启动应用」管理页快捷按钮；用户手动关闭后点「重新实测」复扫变绿。
2. **系统时钟 NTP 同步偏差** `[管理员一键]`
   - 查：实测本机时间与 UTC 偏差（正常范围 `±30s`）。
   - 处理：超限时一键执行 `w32tm /resync /force`（并确认自动对时开启）→ 复测偏差回到 `±30s` 内变绿。
3. **防火墙 Kill Switch 权限就绪** `[管理员一键]`
   - 查：追踪 MSIX `Claude.exe` 路径并实测是否具备免 UAC 读写 `FDClaudeGuard_KillSwitch_*` 防火墙规则权限。
   - 处理：未就绪时一键安装本地免 UAC 守护计划任务并实测读写一条探针规则 → 验收通过变绿。

## 4. 守卫配置全可控开关 & 防火墙自愈安全阀

1. **显示桌面悬浮状态窗（默认：开）**：与主界面顶部标题栏右侧悬浮窗纯图标开关、悬浮窗关闭键及系统托盘实时双向同步；
2. **桌面预警消息提醒（默认：开）**：与主界面顶栏铃铛开关双向同步；关闭仅静音普通预警，熔断与防裸奔危急警报不可静音；
3. **开机自动启动（默认：开）**：随 Windows 开机启动守护引擎；
   - 子选项：**开机时仅显示桌面悬浮窗，不弹出主控制台（默认：开）**，做到零打扰无感护航；
4. **休眠唤醒 / 切网 5 秒预阻断安全窗（默认：开）**：监听 Windows 电源事件（`PBT_APMSUSPEND` / `PBT_APMRESUMEAUTOMATIC`）与网卡变更，唤醒/切网瞬间先挂上临时出站保护，待 Clash 命名管道 + 真实出口复测确认回到白名单节点后毫秒级自动放行，彻底杜绝“睡醒前 3 秒偷跑”；
5. **防裸奔自动接管（默认：开）**：监听 `Claude.exe` 拉起，环境未通过必须项时 `< 100ms` 拦截出站并弹出控制台接管；
6. **紧急断流 & 4 层防回传策略（默认：开）**：
   - 第 1 层：Clash `DELETE /connections` 毫秒掐流 + Windows 防火墙封死出站；
   - 第 2 层：熔断恢复前强杀进程（跳过 `onQuitCleanup` 丢弃内存待传队列）+ 清空 `~/.claude/telemetry/` 离线缓存；
   - 第 3 层：Clash 规则层 `REJECT` 第三方纯遥测域名（Sentry/Datadog/Statsig/Intercom）；
   - 第 4 层：监测 Chrome 桥接 / `get_device_info` 上报频次并提醒；
7. **防火墙「防自锁 / 崩溃与卸载自愈」安全阀**：
   - 本工具写入的全部 Defender 防火墙规则统一采用固定前缀 **`FDClaudeGuard_KillSwitch_*`**；
   - 安装包卸载钩子（NSIS Uninstall Hook）自动清空全部 `FDClaudeGuard_KillSwitch_*` 规则；
   - 「环境维护」内提供独立的 **「清除本工具全部防火墙规则（防自锁救援）」** 一键恢复按钮；正常退出软件前检测存在阻断规则时弹出清理确认；
8. **安全退出防呆提醒（默认：开）**：关闭守卫或准备停用代理时若检测到 Claude 后台残留进程则弹窗提醒；
9. **新号 / 刚付费 24h 冷静保护模式（默认：关，可一键开启）**。

## 5. 节点评估（Claude + Gemini 双平台支持 & 纯净度）与三档容灾切换

### 5.1 双平台可用性与纯净度评估（填补节点表冗余留白，支持一机多 AI）
很多支持 Claude 的节点会被 Google/Gemini 锁区、送中（广播 IP 误判 CN）或触发人机限制。节点评估表在「延迟/抖动」与「24h 断连率」之间合理排布 **「平台支持 / 纯净度」** 列（消除空列留白，保证整表列距匀称）：
- **无状态双平台探测（绝不携带任何账号 Cookie/Token，支持并发限流与缓存防刷）**：
  1. **Claude 可达性（硬门禁参考）**：经目标节点无状态探测 `api.anthropic.com` / `claude.ai` TLS 与 HTTP 响应，识别 `Claude ✓`（绿） / `CF 403`（红） / `禁区`（红）；
  2. **Gemini / Google 支持性（选节点加分参考，不阻断 Claude 启动）**：经目标节点无状态探测 Google AI / Gemini 端点可达性与地区归属判定（如检测 `gemini.google.com` / `generativelanguage.googleapis.com` 是否返回地区不支持或 Google 地理“送中”），识别 `Gemini ✓`（绿） / `受限`（黄灰） / `送中/不可用`（红）；
  3. **ASN 纯净度**：区分 `ISP 住宅/静态` vs `机房/共享`。
- **推荐排序与 UI 纠偏**：
  - 同等延迟/稳定度下，优先给 **Claude + Gemini 双通** 节点标注「双 AI 推荐」；但若某节点仅支持 Claude 不支持 Gemini，仅清晰标示 `Claude ✓ · Gemini ✗`，**绝不因此阻断 Claude 启动**；
  - Mihomo 连接状态卡片严禁使用易引起误解的“已直连”，统一改用 **`管道已连接 (Claude-Fixed)`** 或 **`代理引擎在线`**。

### 5.2 三档容灾切换（清晰提示 + 尊重用户选择）
所有波动/故障/跨区切换弹窗均严格呈现 4 项清晰信息：
1. **故障原因**（哪里出了问题，如 `US-LA-Static-01 连续 3 次探测超时 >15s`）；
2. **当前状态**（防火墙是否已保护、当前 Claude 后台进程数）；
3. **明确建议等待时长**（短期抖动建议等待 `1~2 分钟` 自愈；同区热备清零进程后可立即接管；被迫跨国切换建议静默等待 `15~30 分钟` 避免跨洲瞬移）；
4. **用户最终决定权**：主按钮为推荐安全路径，次级始终保留 **「忽略风险，立即执行」**，绝不死锁用户。

## 7. Claude 进程清零「防复活持续盯防机制（Kill-Hold 押运锁）」

> **痛点背景**：MSIX / Electron 版 Claude Desktop 在被强杀后，常因崩溃自拉起、更新器（`Update.exe`）、IDE 插件或 Chrome 桥接宿主（`chrome-native-host.exe`）在 **1~10 秒内短时间自动重启复活**，若仅强杀一次就继续切节点、清理目录或关代理，极易引发文件占用失败或瞬间裸奔漏包。

1. **全链路自动触发源（手动/自动任意强杀动作均自动接入）**：
   - 侧边栏点击「彻底退出后台进程」；
   - 「环境维护」执行「应急清理缓存」「一键备份并纯净清理」「一键还原快照」；
   - 「节点流量」切换节点弹窗执行「先清空 Claude 进程」；
   - 触发紧急熔断（地区漂移 / 代理断开 / 防裸奔拦截）自动强杀。
2. **两档押运锁策略（高频 250ms 盯防，冒头即杀）**：
   - **短时静默押运（默认 `45 秒`，可在 `30s / 45s / 60s` 间配置，每次拦截复活顺延 `+15 秒`）**：覆盖全部关联进程树（`Claude.exe`、`claude.exe`、`claude-code`、Claude `chrome-native-host`），后台以 `250ms` 高频巡检（或 Windows 进程创建事件监听），窗口期内一旦发现任何关联进程复活立刻再次强杀，累计“已拦截复活 N 次”，并顺延 `+15 秒`（完全覆盖 IDE 插件与扩展常见的 `15s / 30s` 退避重连周期）；
   - **事务级全程押运（Operation Hold）**：执行「备份清理 / 快照还原 / 节点切换 / 熔断未恢复」期间，押运锁持续保持锁定直至事务彻底完成，彻底杜绝操作中途进程复活导致目录被锁或偷发遥测。
3. **无冲突安全释放**：
   - 用户点击控制台 **「安全启动 Claude」** 时，自动在拉起进程前瞬间优雅释放押运锁（绝不误杀用户主动安全启动的 Claude）；
   - 侧边栏「Claude 进程」小卡与悬浮窗 `进程` 微卡片实时展示 `盯防中 (Xs · 已拦 N 次)` 状态，并提供一键「解除盯防」快捷操作以备手工调试。
