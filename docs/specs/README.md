# 需求方案与讨论细节沉淀库（Specs · 彻底防上下文压缩失忆）

> **为什么建这个目录？**  
> 长对话讨论复杂需求时，最容易在上下文压缩（`/compact`）或跨会话续聊后丢掉“刚才讲好的细节点、明确不做的边界、以及为什么否决了方案 B”。  
> 本目录专门用来**实时沉淀每个需求专题的讨论细节与定稿规格**，让任何新会话只需读取 1 份几 KB 的 `SPEC-*.md` 即可 100% 满血续聊/开工。

---

## 一、强制操作守则（AI 与开发者共同遵守）

1. **何时新建 Spec**：
   - 凡进入多轮方案讨论、或包含 3 个以上交互/逻辑/边界细节的需求（如「账户审计分类重构」「控制台单号卫生确认与排序」「4 层熔断优化」「多账户轮流隔离」），**立即复制 [`_TEMPLATE-spec.md`](./_TEMPLATE-spec.md) 新建 `docs/specs/SPEC-<编号>-<简短英文名>.md`**（例如 `SPEC-F02-single-account-confirm.md`）。
   - 简单 1~2 行样式微调（如间距调整）直接登记在 `docs/active/feature-backlog.md`，不必过度建 Spec。
2. **边讨论边落盘（绝不靠聊天记录记忆）**：
   - 每轮讨论只要敲定了新需求点、改了方案、或否决了某条思路，**当轮即原地更新对应 `SPEC-*.md` 的「已敲定细节」「否决方案记录」与「讨论增量日志」**。
3. **上下文压缩前 / 换会话前的必做动作**：
   - 准备压缩上下文或结束讨论前，核查该 `SPEC-*.md` 的「待决问题」与「下一步入口」是否最新；
   - 恢复讨论或交给开发会话时，只需指定读该份 `SPEC-*.md`，**无需翻阅几十轮旧聊天或大体积历史文档**。
4. **上线后冷归档**：
   - 该需求开发验收并随正式版发布后，将 `SPEC-*.md` 移入 `docs/archive/specs/`，保持 `docs/specs/` 里永远只有当前活跃讨论/开发中的方案。
